# Завдання: Журнал системних подій на BroadcastReceiver, Flow та Jetpack Compose

## Мета завдання
Опанувати практичне використання системного компонента **`BroadcastReceiver`** у поєднанні з сучасним реактивним стеком: перетворення системних подій у потік даних за допомогою **`callbackFlow`**, інкапсуляція списку у **`ViewModel` (`StateFlow`)** та побудова інтерактивного журналу подій на **Jetpack Compose** (`LazyColumn`, `ExpandableCard` з анімацією видалення).

---

## Вимоги до функціоналу застосунку

1. **Динамічне слухання системних подій:**
   Додаток підписується на декілька системних бродкастів (наприклад: підключення/відключення зарядного пристрою, зміна режиму "У літаку", критичний рівень батареї чи підключення навушників).

2. **Журнал подій (`LazyColumn`):**
   Щоразу при надходженні нового бродкасту у список списку додається нова картка із записом про подію.

3. **Розгортана картка події (`ExpandableCard`):**
   * **У згорнутому стані:** Картка відображає **ТІЛЬКИ тип/назву події** (наприклад, *"Зарядний пристрій підключено"* або *"AIRPLANE_MODE_CHANGED"*) та час її виникнення.
   * **У розгорнутому стані:** При натисканні на картку вона розгортається і відображає **всі деталі**: детальний опис, точний часовий штамп та додаткові параметри (`Extras`), передані у системному `Intent`.

4. **Видалення картки зі списку:**
   Кожна картка повинна мати кнопку видалення (іконка кошика), натискання на яку вилучає цей конкретний запис із журналу.

5. **Плавні анімації та збереження стану:**
   При додаванні нового бродкасту чи видаленні картки повинна працювати плавна анімація (`Modifier.animateItem()`), а стан розгортання кожної картки повинен зберігатися при скролі завдяки унікальним ключам `key`.

---

## Вимоги до архітектури

* **Model (`BroadcastRepository`):**
  Використовує білдер **`callbackFlow { ... }`** для створення `Flow<BroadcastEvent>`. Забезпечує динамічну реєстрацію `registerReceiver()` із прапорцем `RECEIVER_NOT_EXPORTED` та обов'язковим відписуванням у `awaitClose { unregisterReceiver(...) }`.
* **ViewModel (`BroadcastViewModel`):**
  Перетворює `callbackFlow` у `StateFlow<List<BroadcastEvent>>` за допомогою оператора `stateIn`. Надає методи `deleteEvent(event)` та `clearAll()`.
* **View (Jetpack Compose):**
  Зчитує `StateFlow` за допомогою `collectAsStateWithLifecycle()` та відображає список у `LazyColumn`.

---

## Етапи виконання завдання

### Частина 1: Створення Model (`BroadcastRepository`) та `callbackFlow`
1. Створіть структуру даних `data class BroadcastEvent(val id: String, val type: String, val timestamp: String, val details: String)`.
2. У класі `BroadcastRepository` створіть функцію отримання потоку подій через `callbackFlow`.
3. Створіть `BroadcastReceiver`, який слухає кілька подій (`IntentFilter` із кількома `addAction()`).
4. При надходженні події генеруйте об'єкт `BroadcastEvent` із точним часом та надсилайте його через `trySend(event)`.
5. У блоці `awaitClose { ... }` обов'язково скасовуйте реєстрацію приймача через `unregisterReceiver()`.

---

### Частина 2: Створення ViewModel (`BroadcastViewModel`)
1. У `BroadcastViewModel` створіть змінний список отриманих подій `MutableStateFlow<List<BroadcastEvent>>`.
2. У `viewModelScope` підпишіться на потік подій з репозиторію та додавайте кожну нову подію на початок списку (щоб нові події з'являлися згори).
3. Додайте метод `deleteEvent(event: BroadcastEvent)` для вилучення обраного запису зі списку.

---

### Частина 3: Побудова UI на Jetpack Compose
1. Створіть Composable-компонент **`ExpandableEventCard`**:
   * Внутрішній стан розгортання `var isExpanded by rememberSaveable { mutableStateOf(false) }`.
   * Коли `isExpanded == false` — показується тільки назва події та час.
   * Коли `isExpanded == true` — показується розширений блок деталей події.
   * Додайте кнопку `IconButton` з іконкою кошика `Icons.Default.Delete` для видалення картки.
2. У головному екрані використайте **`LazyColumn`**:
   * Передавайте унікальний ключ `key = { event -> event.id }`.
   * Застосуйте модифікатор `Modifier.animateItem()` для плавного додавання та видалення карток.

---

### Частина 4: Практична перевірка та симуляція через ADB
1. Запустіть додаток на пристрої або емуляторі.
2. Відкрийте термінал і виконайте ADB-команди для симуляції системних подій:
   * **Симуляція живлення:** `adb shell am broadcast -a android.intent.action.ACTION_POWER_CONNECTED`
   * **Симуляція режиму у літаку:** `adb shell am broadcast -a android.intent.action.AIRPLANE_MODE --ez state true`
   * **Симуляція низької батареї:** `adb shell dumpsys battery set level 5`
3. Переконайтеся, що на екрані з'являються нові згорнуті картки.
4. Натисніть на картку для розгортання деталей, перевірте збереження стану при скролі та перевірте видалення картки по кнопці кошика.

Успіхів! Ви побудували сучасний асинхронний журнал системних подій на Jetpack Compose та Kotlin Flow!
