# Практикум: Обробка помилок та Скасування у Корутинах

**Тема:** Кооперативне скасування, ієрархія `Job`, `SupervisorJob`, `supervisorScope` та глобальний обробник `CoroutineExceptionHandler`.

---

### Мета роботи
1. Навчитися правильно скасовувати "важкі" обчислювальні цикли за допомогою `ensureActive()` та `yield()`.
2. Дослідити, як помилка в одній корутині впливає на інші (двостороннє скасування).
3. Використати `SupervisorJob` та `supervisorScope` для ізоляції помилок.
4. Застосувати `CoroutineExceptionHandler` для запобігання крашам додатка.

---

## Блок 1. Кооперативне скасування

Вам потрібно симулювати важкий обчислювальний процес (наприклад, обробку великого масиву даних) та забезпечити можливість його миттєвого скасування користувачем.

1. **Підготовка:**
   * У вашій Activity створіть дві кнопки: `btnStart` та `btnCancel`.
   * Створіть змінну `var calculationJob: Job? = null`.

2. **Запуск важкої задачі:**
   * При натисканні на `btnStart` присвойте `calculationJob` нову корутину, запущену в `lifecycleScope` на `Dispatchers.Default`.
   * Всередині корутини зробіть цикл `for (i in 1..100)`. На кожній ітерації робіть `Thread.sleep(50)` (саме `Thread.sleep`, щоб симулювати блокуючу роботу процесора) та виводьте прогрес у Logcat (наприклад, `"Обробка: $i%"`).
   * Після завершення циклу виведіть `"Роботу успішно завершено!"`.

3. **Скасування без кооперації (Помилка):**
   * При натисканні на `btnCancel` викличте `calculationJob?.cancel()`.
   * **Перевірка:** Запустіть застосунок, натисніть Start, а через 2 секунди — Cancel. Переконайтеся в Logcat, що цикл **НЕ зупинився**, незважаючи на виклик `cancel()`.

4. **Додавання кооперації (Виправлення):**
   * Всередині циклу `for`, одразу після `Thread.sleep(50)`, додайте виклик `ensureActive()`.
   * Огорніть весь цикл у блок `try-catch (e: CancellationException)`. У блоці `catch` виведіть лог `"Обробку скасовано користувачем!"`, після чого обов'язково прокиньте помилку далі (`throw e`).
   * **Перевірка:** Запустіть знову. Тепер при натисканні Cancel цикл має миттєво зупинитися, а в логах з'явиться відповідне повідомлення.

## Блок 2. Ланцюгова реакція при помилках

Зараз ми перевіримо, як падіння однієї дочірньої корутини вбиває всі інші в рамках звичайного `Job`.

1. **Створення тестового середовища:**
   * Створіть кнопку `btnTestCrash`.
   * При натисканні запустіть батьківську корутину `lifecycleScope.launch`.

2. **Запуск дочірніх корутин:**
   * Всередині неї запустіть **першу дочірню корутину** (симуляція завантаження банера): вона робить `delay(1000)`, після чого викидає `throw RuntimeException("Банер не завантажився!")`.
   * Запустіть **другу дочірню корутину** (симуляція завантаження стрічки новин): вона робить `delay(2000)` і виводить лог `"Стрічка новин завантажена"`.

3. **Результат (Краш):**
   * Натисніть кнопку. Ви побачите, що застосунок вилетів (crash).
   * Що важливіше: повідомлення `"Стрічка новин завантажена"` **НІКОЛИ не з'явиться**, оскільки перша корутина впала і потягнула за собою батька та "сестру".

---

## Блок 3. Ізоляція помилок через SupervisorScope

Спробуємо захистити другу корутину від падіння першої, а сам додаток — від крашу.

1. **Використання `supervisorScope`:**
   * Змініть код із Блоку 2: огорніть запуск обох дочірніх корутин у блок `supervisorScope { ... }`.
   
2. **Перехоплення помилки (try-catch):**
   * Як ви знаєте з теорії, `supervisorScope` не ковтає краші. Тому всередині **першої** дочірньої корутини огорніть виклик `throw RuntimeException(...)` у `try-catch (e: Exception)`.
   * У блоці `catch` виведіть лог (через `Log.e`), що банер не вдалося завантажити.

3. **Перевірка:**
   * Запустіть застосунок і натисніть кнопку.
   * **Що має відбутися:** Додаток НЕ падає. У Logcat з'являється помилка банера, а ще через секунду успішно з'являється лог `"Стрічка новин завантажена"`. Ізоляція працює!

## Блок 4. Глобальний запобіжник (CoroutineExceptionHandler)

Що робити, якщо ми забули написати `try-catch`? Додамо глобальний обробник.

1. **Створення обробника:**
   * Вгорі вашої `Activity` (або всередині методу `onCreate`) створіть об'єкт обробника:
     ```kotlin
     val ceh = CoroutineExceptionHandler { _, throwable ->
         Log.e(TAG, "Глобальне перехоплення крашу: ${throwable.message}")
     }
     ```

2. **Тестування обробника:**
   * Створіть нову кнопку `btnGlobalCrash`.
   * У слухачі натискання створіть кастомний Scope із `SupervisorJob`, Головним потоком та вашим обробником:
     ```kotlin
     val safeScope = CoroutineScope(SupervisorJob() + Dispatchers.Main + ceh)
     ```
   * Запустіть корутину `safeScope.launch { ... }`.
   * Всередині зробіть `delay(500)` і викиньте будь-яку помилку (наприклад, `throw IllegalArgumentException("Ой!")`). **НЕ використовуйте** тут `try-catch`!

3. **Перевірка:**
   * Натисніть кнопку.
   * Додаток **не повинен впасти**. Натомість у Logcat має з'явитися повідомлення з вашого `CoroutineExceptionHandler`.

## Додаткове завдання (із зірочкою ⭐)

**Пастка вкладеності:**
Спробуйте передати ваш `ceh` не в `CoroutineScope`, а **безпосередньо у внутрішню дочірню корутину**, запущену від `lifecycleScope`:
```kotlin
lifecycleScope.launch {
    launch(ceh) { // Передаємо обробник сюди
        throw RuntimeException("Вкладений краш!")
    }
}
```
Запустіть код. Що відбулося з додатком і чому? Чи з'явився лог з `ceh`? 
*(Підказка: згадайте 2-ге Золоте правило з довідника)*.
