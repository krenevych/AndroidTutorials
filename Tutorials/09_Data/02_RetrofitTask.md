# Завдання: Застосунок «ПриватБанк — валюти» (Retrofit та MVVM)

## Мета завдання

Навчитися отримувати дані з REST API за допомогою **Retrofit**, перетворювати JSON на Kotlin-моделі та відображати список у **Jetpack Compose**. Закріпити архітектуру **MVVM**: зберігати обрану дату та стан завантаження у **ViewModel**, щоб застосунок правильно працював після повороту екрана.

---

## Початкові умови

Перед виконанням опрацюйте туторіал [«Робота з мережею: Retrofit та OkHttp»](../../Documentation/09_Data/02_Retrofit.md).

Ви можете використати заготовку з репозиторію [krenevych/Compose](https://github.com/krenevych/Compose) (гілка **`main`**, модуль **`private24`**) або власний Compose-проєкт.

Джерело даних — [публічне API ПриватБанку](https://api.privatbank.ua/), розділ [«Архів курсів валют»](https://api.privatbank.ua/#p24/exchangeArchive). Опис архівного запиту також доступний в [офіційній документації LiqPay / ПриватБанку](https://www.liqpay.ua/en/doc/api/public/archive?tab=0).

---

## Опис та вимоги до застосунку

Розробіть застосунок **«ПриватБанк — валюти»**, який завантажує та показує курси валют **на обрану користувачем дату**.

На головному екрані повинні бути:

1. **Вибір дати** — через календар (`DatePickerDialog`) або текстове поле у форматі `dd.MM.yyyy`.
2. **Кнопка «Показати курси»** — завантажує дані для обраної дати. Повторне натискання оновлює результат.
3. **Список валют (`LazyColumn`)** — для кожної валюти відобразіть її код, курс купівлі та курс продажу ПриватБанку до гривні. Поруч зі списком укажіть дату, до якої належать завантажені курси.
4. **Стани екрана** — індикатор завантаження, список отриманих курсів, повідомлення про відсутність даних або помилку з можливістю повторити запит.
5. **Збереження стану при повороті екрана** — обрана дата, отримані курси та поточний стан завантаження не повинні скидатися. Сам поворот не повинен створювати додатковий мережевий запит.

Якщо курс купівлі або продажу для валюти відсутній, показуйте **«—»** або **«Немає даних»**. Не підставляйте `0` чи курс НБУ замість відсутнього курсу ПриватБанку.

## Етапи виконання завдання

### Частина 1: Дослідження API та підготовка проєкту

1. Відкрийте документацію архівного API та перегляньте відповідь на запит. Приклад адреси:

   ```text
   https://api.privatbank.ua/p24api/exchange_rates?json&date=01.11.2026
   ```

   Параметр `date` задає дату у форматі **`dd.MM.yyyy`**, а `json` — формат відповіді. За документацією архів охоплює останні **4 роки**: обирайте дати в доступному діапазоні та не дозволяйте запитувати майбутню дату.

2. Зверніть увагу на структуру відповіді: це **об'єкт**, усередині якого є масив **`exchangeRate`**. У туторіалі про поточні курси сервер повертав масив без такої обгортки.
3. Додайте дозвіл `INTERNET` у `AndroidManifest.xml` та залежності Retrofit і конвертера Gson, як у туторіалі.

### Частина 2: Створення моделей та мережевого шару

1. Створіть `data class` для всієї відповіді, наприклад `ExchangeArchiveResponse`, та окремий клас для одного елемента `exchangeRate`.
2. Зіставте потрібні поля JSON із властивостями моделей:

   | Поле JSON | Призначення |
   | --- | --- |
   | `date` | Дата отриманих курсів у кореневому об'єкті |
   | `exchangeRate` | Список курсів валют |
   | `currency` | Код валюти, наприклад `USD` або `EUR` |
   | `baseCurrency` | Базова валюта в елементі списку, наприклад `UAH` |
   | `purchaseRate` | Курс купівлі ПриватБанку |
   | `saleRate` | Курс продажу ПриватБанку |
   | `purchaseRateNB`, `saleRateNB` | Курси НБУ — окремі від курсів ПриватБанку |

3. В архівній відповіді значення курсів є **JSON-числами**. Для їх відображення можна використати `Double`, а для необов'язкових курсів ПриватБанку — `Double?`. Записи без коду валюти не додавайте до видимого списку.
4. Створіть інтерфейс API. Використайте `@GET("exchange_rates?json")` та передавайте дату через `@Query("date")`. Результат має містити весь об'єкт відповіді, наприклад `Call<ExchangeArchiveResponse>`.
5. Налаштуйте Retrofit із базовою адресою `https://api.privatbank.ua/p24api/` та `GsonConverterFactory`. Виконуйте запит асинхронно через `enqueue()`, як у туторіалі.

### Частина 3: ViewModel та стан екрана

1. Створіть `ExchangeArchiveViewModel`. Зберігайте в ній **обрану дату** та **стан запиту**, а не лише список курсів.
2. Опишіть стан через `sealed interface` або `data class`. Передбачте початковий стан до першого запиту, завантаження, успіх і помилку. Порожній список успішної відповіді обробляйте окремим повідомленням у UI.
3. Надайте UI публічний `StateFlow`, а зміну стану виконуйте через приватний `MutableStateFlow`.
4. Додайте методи зміни дати та завантаження курсів. Перед запитом перевіряйте коректність дати; для текстового введення відхиляйте також неіснуючі дати, наприклад `31.02.2026`.
5. У `onResponse()` перевіряйте HTTP-статус та наявність тіла відповіді. У `onFailure()` показуйте зрозуміле повідомлення, наприклад «Не вдалося завантажити курси. Перевірте з'єднання та спробуйте знову».
6. Для простоти вимикайте вибір дати та кнопку завантаження на час запиту. Зберігайте поточний `Call` у ViewModel та скасовуйте незавершений виклик у `onCleared()`.

**Розподіл відповідальності:** мережевий шар отримує дані; ViewModel керує запитом і станом; Compose показує стан та передає дії користувача. ViewModel не повинна зберігати посилання на Activity або UI-компоненти.

### Частина 4: UI на Jetpack Compose

1. Створіть екран із вибором дати, кнопкою та `LazyColumn` для валют.
2. Отримуйте ViewModel через `viewModel()`, а її стан — через `collectAsStateWithLifecycle()`.
3. Залежно від стану показуйте підказку обрати дату, `CircularProgressIndicator`, список валют або повідомлення про помилку чи відсутність даних.
4. Показуйте курси з підписами **«Банк купує»** та **«Банк продає»** і вказуйте базову валюту. Купівля та продаж визначаються з погляду банку.
5. Після помилки дозвольте повторити запит для тієї самої дати.

> 💡 **Важливо для повороту екрана:** не запускайте завантаження безпосередньо в тілі composable або при кожному `onCreate()`. У цьому завданні запит запускає кнопка, а нова Activity після повороту підписується на стан тієї самої ViewModel. Не вимикайте поворот екрана та не обходьте перестворення Activity через `android:configChanges`.

### Частина 5: Практична перевірка

1. Оберіть дату, завантажте курси та порівняйте кілька значень із відповіддю API для тієї самої дати.
2. **Поверніть екран після завантаження:** дата та список повинні залишитися. Перевірте за власним логом початку запиту в Logcat, що нового виклику API не виникло.
3. **Поверніть екран під час завантаження:** запит має продовжитися у ViewModel, а результат — відобразитися у новому екземплярі екрана. Для перевірки швидкого запиту можна увімкнути уповільнення мережі в налаштуваннях емулятора.
4. Оберіть іншу дату та повторіть запит. Переконайтеся, що список і підпис його дати відповідають новій відповіді.
5. Вимкніть Інтернет і спробуйте оновити курси. Застосунок має показати помилку без аварійного завершення. Поверніть з'єднання та повторіть запит.
6. Перевірте некоректну дату, порожній список і запис без курсів ПриватБанку. Якщо API не повернув потрібний випадок, тимчасово підставте відповідні тестові дані для перевірки UI.
