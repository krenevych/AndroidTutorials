# Завдання: Власний Application та Життєвий цикл процесу

## Мета завдання
Навчитися створювати власний клас `Application`, реєструвати його в маніфесті, виконувати глобальну ініціалізацію бібліотек (на прикладі Timber) та використовувати інструменти командного рядка (ADB) для відстеження життєвого циклу процесу застосунку.

## Частина 1: Створення та налаштування Application

1. **Підготовка проекту:**
   * Створіть новий проект в Android Studio (або візьміть будь-який з попередніх).
   * Додайте бібліотеку Timber у файл `build.gradle.kts` вашого модуля:
     ```kotlin
     implementation("com.jakewharton.timber:timber:5.0.1")
     ```
   * Синхронізуйте проект (Sync Now).

2. **Створення кастомного Application:**
   * Створіть новий Kotlin-клас з назвою `MyApp` (чи будь-якою іншою) та унаслідуйте його від `android.app.Application`.
   * Перевизначте метод `onCreate()`.
   * У методі `onCreate()` додайте ініціалізацію Timber так, щоб вона працювала **лише у Debug-збірці** (використайте `BuildConfig.DEBUG`).
   * Зареєструйте ваш клас `MyApp` у файлі `AndroidManifest.xml`.

3. **Використання Timber:**
   * У вашій `MainActivity` (в методі `onCreate`) видаліть звичайний `Log.d` (якщо він там був) і напишіть повідомлення за допомогою Timber:
     ```kotlin
     Timber.d("MainActivity успішно запущена!")
     ```
   * Запустіть застосунок на пристрої/емуляторі та переконайтеся, що в панелі **Logcat** з'явилося ваше повідомлення (тег має згенеруватися автоматично і відповідати назві класу, тобто `MainActivity`).

## Частина 2: Дослідження процесу через ADB

Тепер ми перевіримо, як живе процес вашого застосунку в пам'яті операційної системи.
Для виконання цього завдання вам знадобиться вкладка **Terminal** внизу вікна Android Studio (або системна консоль, якщо ADB налаштовано в змінних середовищах).

**Крок 1. Запуск та пошук процесу:**
* Запустіть ваш застосунок на пристрої/емуляторі (екран має бути відкритим).
* У терміналі виконайте команду для пошуку процесу за вашим пакетом. Наприклад (замініть `com.example.myapp` на ваш реальний пакет):
  ```bash
  adb shell "ps -A -o PID,NAME" | grep -E "PID|com.example.myapp"
  ```
* Знайдіть у виводі номер вашого процесу (PID) і запишіть його собі (наприклад, 14532).

**Крок 2. Згортання застосунку (Background):**
* На пристрої натисніть кнопку "Home", щоб згорнути застосунок (але не закривайте його через меню багатозадачності!).
* Виконайте ту саму команду `adb shell...` ще раз. 
* *Питання для самоперевірки:* Чи змінився PID? Чи процес досі "живе" в пам'яті?

**Крок 3. Примусове вбивство процесу:**
* Спробуємо зімітувати ситуацію, коли Android вбиває ваш процес через брак пам'яті. Виконайте в терміналі наступну команду (використайте PID з першого кроку):
  ```bash
  adb shell kill -9 <ВАШ_PID>
  ```
* Подивіться на екран пристрою/емулятора. Якщо ваш застосунок був на передньому плані, він різко закриється.
* Виконайте команду пошуку ще раз:
  ```bash
  adb shell "ps -A -o PID,NAME" | grep -E "PID|com.example.myapp"
  ```
* *Питання для самоперевірки:* Чи є тепер ваш застосунок у списку процесів?

**Крок 4. Відновлення:**
* Відкрийте меню нещодавніх програм (Recent Apps) на пристрої і натисніть на ваш застосунок (або просто запустіть його з іконки на робочому столі).
* Знову виконайте команду пошуку:
  ```bash
  adb shell "ps -A -o PID,NAME" | grep -E "PID|com.example.myapp"
  ```
* *Питання для самоперевірки:* Чи співпадає новий PID з тим, що був на Кроці 1? Подумайте, чому так сталося і чи зберігся б об'єкт вашого класу `MyApp` між цими двома запусками.

## Додаткове завдання (із зірочкою ⭐)
* У вашому класі `MyApp` додайте глобальну змінну: `var startCount = 0`.
* При кожному натисканні на кнопку в `MainActivity` збільшуйте цю змінну на `1` (через звернення `(application as MyApp).startCount++`) і виводьте її поточне значення через Timber.
* Проведіть експеримент: наклікайте кнопку (щоб лічильник став, наприклад, 5). Згорніть програму. Вбийте процес через `adb shell kill -9`. Відкрийте програму знову і натисніть кнопку. Яке значення виведе Timber і чому?
