# Практикум: Базова робота з Gradle в Android 

**Тема:** Основи Gradle Wrapper (`gradlew`), розуміння структури проекту, конфігурація модуля
`app/build.gradle.kts`, типи залежностей (`implementation`, `testImplementation`) та базовий каталог
версій (`libs.versions.toml`).

---

### Мета роботи

1. Навчитися запускати та контролювати процес збірки через консоль без використання кнопок Android
   Studio.
2. Розібратися в призначенні ключових параметрів блоку `android { ... }`.
3. Опанувати додавання зовнішніх бібліотек сучасним методом через `libs.versions.toml`.
4. Створити першу найпростішу кастомну задачу.

---

## Блок 1. Командний рядок Gradle Wrapper

Всі команди виконуються в терміналі кореневої папки проекту через `./gradlew` (на macOS/Linux) або
`gradlew.bat` (на Windows).

1. **Базові команди життєвого циклу:**
    * Очистіть проект від попередніх артефактів збірки командою `clean`.
    * Зберіть налагоджувальну версію додатку за допомогою задачі `assembleDebug`.
    * Перевірте папку `app/build/outputs/apk/debug/` та переконайтеся у створенні готового файлу
      `.apk`.
2. **Перегляд задач та версії:**
    * Виведіть перелік усіх доступних задач збірки проекту (`./gradlew tasks`).
    * Перегляньте поточну версію Gradle та середовища виконання (`./gradlew --version`).

## Блок 2. Базова конфігурація модуля (`app/build.gradle.kts`)

Відкрийте файл конфігурації модуля `app` та виконайте налаштування:

1. **Керування параметрами версійності:**
    * Змініть `versionCode` на `2`, а `versionName` на `"1.0.1"`.
    * Зверніть увагу на параметри `minSdk`, `targetSdk` та `compileSdk` — зафіксуйте у звіті, за що
      відповідає кожен із них.
2. **Розділення додатків на пристрої (`applicationIdSuffix`):**
    * У блоці `buildTypes { debug { ... } }` додайте директиву `applicationIdSuffix = ".debug"`.
    * Зберіть додаток та встановіть його на пристрій: переконайтеся, що пакет тепер має вигляд
      `com.example.myapp.debug` (це дозволяє тримати debug і release версії одночасно на одному
      телефоні).

## Блок 3. Робота із залежностями та Version Catalog

Переведіть підключення залежностей на централізований файл `gradle/libs.versions.toml`.

1. **Додавання нової бібліотеки:**
    * Відкрийте `gradle/libs.versions.toml`.
    * У секції `[versions]` додайте версію для бібліотеки роботи із зображеннями Coil (наприклад,
      `coil = "2.6.0"`).
    * У секції `[libraries]` опишіть артефакт:
      `coil = { module = "io.coil-kt:coil", version.ref = "coil" }`.
2. **Підключення в проект:**
    * У файлі `app/build.gradle.kts` у блоці `dependencies` підключіть бібліотеку через типізований
      доступ:
      ```kotlin
      implementation(libs.coil)
      ```
3. **Розуміння конфігурацій (Scope):**
    * Поясніть різницю між `implementation` та `testImplementation`.
    * Знайдіть у блоці `dependencies` бібліотеку JUnit та визначте, чи потрапить вона у фінальний
      APK-файл додатку.

## Блок 4. Перша власна задача (Custom Task)

Наприкінці файлу `app/build.gradle.kts` опишіть власну задачу для перевірки стану проекту:

1. Зареєструйте задачу `printProjectInfo`:
   ```kotlin
   tasks.register("printProjectInfo") {
       doLast {
           println("--- Інформація про модуль ---")
           println("Модуль: ${project.name}")
           println("Шлях до збірки: ${project.buildDir}")
       }
   }
    ```
   
2. Виконайте команду `./gradlew printProjectInfo` у терміналі та перевірте результат виводу.
