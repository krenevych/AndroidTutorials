# Корутини та Побічні ефекти (Side-Effects) у Compose

У Jetpack Compose існує золоте правило: **Composable-функції мають бути вільними від побічних ефектів (Side-Effect Free)**. Це означає, що вони не повинні самостійно здійснювати мережеві запити, записувати дані в базу чи напряму взаємодіяти з іншими компонентами системи у своєму тілі. 

Оскільки Compose може викликати функцію (робити рекомпозицію) десятки разів на секунду або взагалі паралельно на різних потоках, будь-який важкий запит, написаний просто всередині функції, "покладе" ваш додаток!

Проте, як же тоді запустити Корутину (наприклад, щоб показати `Snackbar` або зробити запит) після натискання на кнопку чи при першому відкритті екрану? Для цього існують спеціальні **Effect API**.

---

## 1. Запуск корутин по кліку: `rememberCoroutineScope`

У традиційному Android ми використовували `lifecycleScope.launch { ... }` всередині `Activity` чи `Fragment`. Але в Compose ми не можемо і не повинні передавати `lifecycleScope` ззовні у кожну Composable-функцію! 

Compose має власний, набагато "розумніший" механізм керування корутинами, прив'язаний до життєвого циклу самої Composable-функції на екрані. Цей механізм називається **`rememberCoroutineScope()`**.

### Коли використовувати `rememberCoroutineScope`?
Використовуйте його **ВИКЛЮЧНО всередині колбеків** (наприклад, `onClick` кнопки або жесту `onRefresh`), коли вам потрібно запустити `suspend` функцію у відповідь на дію користувача.

```kotlin
@Composable
fun SaveButtonScreen(repository: MyRepository) {
    // 1. Отримуємо Scope, який прив'язаний саме до цього екрану Compose!
    val scope = rememberCoroutineScope()
    
    // Стан для відображення результату
    var message by remember { mutableStateOf("") }

    Column(modifier = Modifier.padding(16.dp)) {
        Button(
            // ❌ ЗАБОРОНЕНО писати suspend функції прямо в onClick без scope.launch
            onClick = { 
                // 2. Запускаємо корутину у Scope цього компонента
                scope.launch { 
                    message = "Зберігаємо..."
                    // Викликаємо важку suspend функцію
                    val result = repository.saveData() 
                    message = if (result) "Успіх!" else "Помилка"
                }
            }
        ) {
            Text("Зберегти дані")
        }

        Text(text = message)
    }
}
```

> 💡 **Чому це краще за `lifecycleScope` і чи потрібен тут `cancel()`?**
> Об'єкт `CoroutineScope`, повернутий `rememberCoroutineScope()`, жорстко прив'язаний до точки в дереві Compose, де він був викликаний. Якщо користувач піде з цього екрану (функція `SaveButtonScreen` зникне з композиції), **усі корутини, запущені через цей `scope`, будуть миттєво скасовані АВТОМАТИЧНО!** 
> 
> Вам **не потрібно** вручну викликати `scope.cancel()` або відстежувати життєвий цикл. Compose сам турбується про те, щоб не було жодних витоків пам'яті (Memory Leaks) або крашів після закриття екрану.

## 2. Запуск корутини при відкритті екрану: `LaunchedEffect`

Що робити, якщо нам потрібно запустити корутину **НЕ по кліку**, а автоматично — відразу при появі екрану (наприклад, щоб стягнути список новин з сервера)?

Тут не можна використовувати `rememberCoroutineScope()`. Для автоматичного запуску при вході в композицію використовується **`LaunchedEffect`**.

### Як працює `LaunchedEffect`?
Це спеціальна Composable-функція, яка автоматично запускає корутину всередині себе. Вона має життєвий цикл:
1. Запускається, щойно додається на екран.
2. Автоматично скасовується, щойно зникає з екрану.

### Параметр `key` (Ключ перезапуску)
`LaunchedEffect` вимагає передати **ключ** (`key1`, `key2`...). Корутина запуститься один раз при старті екрану, а потім **буде скасована і перезапущена заново ТІЛЬКИ у тому випадку, якщо значення цього ключа зміниться**!

#### Приклад 1: Одноразовий запуск (Ключ `Unit`)
Якщо ви хочете, щоб корутина виконалася лише 1 раз при відкритті екрану і більше ніколи не перезапускалася при перемальовуванні UI, передайте ключ `Unit` (або `true`):

```kotlin
@Composable
fun NewsScreen(viewModel: NewsViewModel) {
    // Корутина виконається рівно 1 раз при відкритті NewsScreen
    LaunchedEffect(key1 = Unit) {
        viewModel.fetchNewsFromServer()
    }
    
    // ... малюємо список новин ...
}
```

#### Приклад 2: Запуск, що залежить від змінної (Динамічний ключ)
Якщо ви хочете перезапускати запит на сервер щоразу, коли користувач змінює категорію у фільтрі, передайте цю змінну як ключ:

```kotlin
@Composable
fun StoreScreen(viewModel: StoreViewModel, selectedCategory: String) {
    
    // Корутина автоматично перезапуститься, якщо selectedCategory зміниться!
    // Наприклад, з "Взуття" на "Куртки". Старий запит скасується, новий полетить!
    LaunchedEffect(key1 = selectedCategory) {
        viewModel.loadProductsByCategory(selectedCategory)
    }
    
    // ... малюємо товари ...
}
```

## Підсумок: Що обрати?

| Механізм | Коли використовувати? | Де викликати? |
| :--- | :--- | :--- |
| **`rememberCoroutineScope()`** | У відповідь на **дії користувача** (кліки, свайпи, жести). Наприклад: показати Snackbar або зберегти форму по кліку на `Button`. | Зберігати змінну у тілі `@Composable`, але викликати `launch` **ТІЛЬКИ усередині колбеків** (`onClick = { ... }`). |
| **`LaunchedEffect(key)`** | Для автоматичного запуску логіки, яка **залежить від стану екрану** або життєвого циклу. Наприклад: завантажити дані при відкритті екрану, або запустити анімацію при зміні змінної. | Викликається як звичайна функція прямо **у тілі `@Composable`**. |
| **`viewModelScope.launch`** | Для обробки бізнес-логіки. | **Виключно всередині `ViewModel`**. (Compose взагалі не повинен знати про цей scope). |
