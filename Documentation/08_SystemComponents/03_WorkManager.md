# Гарантоване фонове виконання: WorkManager

У попередньому туторіалі ми дізналися, що для довготривалої роботи у фоні використовується `Foreground Service`. Однак він має серйозний недолік — **він вимагає показу постійного сповіщення**, що дратує користувача.

Що робити, якщо вам потрібно виконати роботу у фоні (наприклад, завантажити логи на сервер, оновити базу даних або щоденно синхронізувати контакти), і вам **не хочеться показувати сповіщення**, а також якщо ви хочете, щоб робота виконалася **гарантовано**, навіть якщо телефон перезавантажиться?

Для цього Google створив бібліотеку **`WorkManager`**.

---

## 1. Що таке WorkManager?
**WorkManager** — це сучасне рішення Jetpack для **гарантованого** відкладеного виконання фонових задач.

### Головні переваги WorkManager:
* **Гарантія виконання:** Задача гарантовано виконається (навіть якщо користувач закрив додаток через свайп або перезавантажив телефон!).
* **Умови виконання (Constraints):** Ви можете задати специфічні системні умови для запуску задачі (наприклад, "тільки коли підключено Wi-Fi" або "тільки якщо телефон на зарядці"). Це шалено економить батарею користувача.
* **Підтримка Корутин:** Ідеально інтегрований з Kotlin Coroutines через клас `CoroutineWorker`.

### Коли використовувати `WorkManager`?
* Періодична синхронізація (кожні 15 хвилин).
* Завантаження аналітики на сервер уночі.
* Стиснення відео чи завантаження фотографій на сервер у фоні.

---

## 2. Створення та запуск задачі у WorkManager

### Крок 1. Залежності
Додайте бібліотеку `WorkManager` (з підтримкою Coroutines) у `build.gradle.kts`:
```kotlin
implementation("androidx.work:work-runtime-ktx:2.9.0")
```

### Крок 2. Створення "Робочого класу" (`CoroutineWorker`)
Ви успадковуєтеся від `CoroutineWorker` і перевизначаєте призупиняючу `suspend` функцію **`doWork()`**, яка автоматично виконується у фоновому потоці (`Dispatchers.Default`):

```kotlin
class SyncWorker(
    context: Context,
    workerParams: WorkerParameters
) : CoroutineWorker(context, workerParams) {

    // Цей код гарантовано запуститься ОС Android у фоновому потоці
    override suspend fun doWork(): Result {
        return try {
            Log.d("WorkManager", "Починаємо синхронізацію...")
            
            // Ваш код...
            val response = apiInterface.syncData() 
            
            Log.d("WorkManager", "Синхронізація успішна!")
            
            // Якщо задача виконана успішно
            Result.success() 
            
        } catch (e: Exception) {
            Log.e("WorkManager", "Помилка мережі", e)
            
            // У разі помилки — просимо систему автоматично повторити спробу пізніше!
            Result.retry() 
        }
    }
}
```

### Крок 3. Запуск задачі з Умовами (`Constraints`)

Ви можете запустити задачу лише один раз (`OneTimeWorkRequest`) або повторювати її періодично (`PeriodicWorkRequest`):

```kotlin
// 1. Створюємо умови для запуску (Constraints)
val constraints = Constraints.Builder()
    .setRequiredNetworkType(NetworkType.UNMETERED) // Тільки на Wi-Fi (безлімітний трафік)
    .setRequiresCharging(true)                     // Тільки якщо телефон на зарядці
    .build()

// 2. Створюємо запит на виконання нашої задачі
val syncRequest = OneTimeWorkRequestBuilder<SyncWorker>()
    .setConstraints(constraints) // Додаємо умови
    .build()

// 3. Ставимо задачу у системну чергу WorkManager
WorkManager.getInstance(context).enqueue(syncRequest)
```

> 💡 **Як це працює під капотом?**
> Ви ставите задачу в чергу і забуваєте про неї. Система Android сама відстежує стан смартфона. Вона дочекається моменту, коли користувач підключить телефон до зарядки та увійде у зону Wi-Fi (навіть уночі!), і тільки тоді "розбудить" ваш додаток та запустить метод `doWork()`!

## 3. Порівняння: Що та коли обрати?

Щоб не помилитися з вибором технології для фонової роботи, запам'ятайте цю шпаргалку:

| Інструмент | Опис | Коли використовувати? |
| :--- | :--- | :--- |
| **`Coroutines`** (`viewModelScope`) | Звичайні асинхронні задачі. Вмирають разом з екраном або при згортанні додатка. | Завантаження даних для відображення на екрані (поки юзер дивиться на екран). |
| **`Foreground Service`** | Безперервна служба з обов'язковим сповіщенням. Працює поки згорнуто додаток. | Музичний плеєр, таймер бігу, завантаження великого фільму, дзвінок. |
| **`WorkManager`** | Гарантоване відкладене виконання задач системою. Без сповіщень. | Синхронізація бази даних вночі на Wi-Fi, відправка аналітики чи бекапів. |

---

## Підсумок

* **`WorkManager`** — інструмент для гарантованих, відкладених у часі фонових задач.
* Задачі формулюються через клас **`CoroutineWorker`** та його призупиняючий метод **`doWork()`**, який автоматично працює у фоні.
* Метод `doWork()` повинен повернути стан: `Result.success()`, `Result.failure()` або `Result.retry()` (для автоматичного повторного запуску).
* Завдяки **`Constraints`** можна задати умови: "тільки Wi-Fi" (`UNMETERED`) або "тільки на зарядці" (`setRequiresCharging`), зберігаючи акумулятор користувача.
