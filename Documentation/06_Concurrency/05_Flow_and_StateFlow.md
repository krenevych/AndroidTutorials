# Реактивні потоки в Kotlin: Flow, StateFlow та SharedFlow

У сучасній Android-розробці для передачі та відстеження асинхронних даних використовуються реактивні потоки **Kotlin Flow**. Вони є сучасною та більш гнучкою заміною застарілому `LiveData`.

---

## 1. Що таке Kotlin Flow та його базові оператори (`flow`, `emit`, `collect`)

> 📦 **Початковий проект:**
> Ви можете завантажити або склонувати заготовку цього проекту з GitHub за посиланням: [krenevych/Concurrency](https://github.com/krenevych/Concurrency) (гілка **`main`**, модуль **`flowfibonacci`**).
> 
> 💡 **Готовий розв'язок (для холодних потоків Flow):**
> Повний робочий код прикладів з холодними потоками можна переглянути на гілці **`flow_end`** (модуль **`flowfibonacci`**).

Якщо звичайна `suspend` функція повертає лише один результат, то **`Kotlin Flow`** — це асинхронний потік, який здатен видавати **послідовність багатьох значень протягом часу** (наприклад, числа Фібоначчі, відсотки завантаження файлу або оновлення лічильника).

```
[ Джерело Flow ] ─── (значення 1) ───► (значення 2) ───► (значення 3) ───► [ Споживач collect ]
```

Робота з базовим `Flow` будується на трьох основних елементах:

### 1. `flow { ... }` (Білдер створення потоку)
Блок-білдер `flow { ... }` створює новий потік даних. Код усередині цього блоку є асинхронним і може кликати будь-які `suspend` функції (наприклад, `delay(1000)` чи мережеві запити), не блокуючи Main Thread.

### 2. `emit(value)` (Надсилання значення у потік)
`emit()` — це `suspend` функція, яка викликається усередині білдера `flow { ... }` для **надсилання нового значення** споживачам.

### 3. `collect { value -> ... }` (Збирання даних з потоку)
`collect()` — це термінальна `suspend` функція, яка **запускає виконання потоку та приймає кожне надіслане значення**. Оскільки `collect()` є `suspend` функцією, викликати її можна **тільки усередині корутини** (наприклад, `lifecycleScope.launch`) або з іншої `suspend` функції.

---

### Приклад використання `flow`, `emit` та `collect`:

Уявіть, що нам потрібно реалізувати асинхронний лічильник, який щосекунди надсилає нове число від 1 до 5 та оновлює його на екрані:

```kotlin
// 1. Створення Flow за допомогою білдера flow та функції emit()
fun getCounterFlow(): Flow<Int> = flow {
    for (i in 1..5) {
        delay(1000) // ⚡ Неблокуюча затримка корутини
        emit(i)     // ⚡ Передаємо нове значення у потік
    }
}

// 2. Підписка та збирання даних за допомогою suspend-функції collect()
lifecycleScope.launch {
    getCounterFlow().collect { value ->
        // Отримуємо кожне нове значення з потоку і оновлюємо UI
        binding.tvCounter.text = "Лічильник: $value"
    }
}
```

---

### `Flow` є "Холодним" (Cold Stream)

За замовчуванням звичайний `Flow` є **Холодним потоком даних**:
* Код усередині білдера `flow { ... }` **взагалі не виконується**, поки у якійсь корутині не викликано метод `.collect()`.
* Для кожного нового підписника (кожного нового виклику `.collect()`) блок `flow { ... }` запускається і виконується з нуля.
* Якщо корутину-споживача скасовано (наприклад, при закритті екрану), виконання коду всередині `flow { ... }` **автоматично зупиняється та скасовується**.

## 2. Основні оператори Flow

Подібно до звичайних колекцій у Kotlin, `Flow` надає багатий набір операторів для трансформації, фільтрації та обробки даних перед тим, як вони потраплять у підписник `.collect()`.

### Огляд популярних операторів Flow:

| Оператор | Призначення / Опис | Приклад |
| :--- | :--- | :--- |
| **`map { ... }`** | Перетворює кожний елемент потоку в інше значення. | `.map { price -> "$price $" }` |
| **`filter { ... }`** | Пропускає тільки ті елементи, які відповідають умові. | `.filter { num -> num % 2 == 0 }` |
| **`onEach { ... }`** | Виконує побічну дію (наприклад, логування) для кожного елемента, не змінюючи його. | `.onEach { Log.d(TAG, "Елемент: $it") }` |
| **`catch { e -> ... }`** | Безпечно перехоплює винятки, вибиті усередині Flow, запобігаючи крашу. | `.catch { e -> Log.e(TAG, "Помилка", e) }` |
| **`onCompletion { ... }`** | Виконується при завершенні Flow (або у разі його скасування/помилки). | `.onCompletion { Log.d(TAG, "Завершено") }` |
| **`flowOn(Dispatcher)`** | Змінює диспатчер виконання для усіх операторів, які знаходяться **вище** нього. | `.flowOn(Dispatchers.IO)` |
| **`distinctUntilChanged()`** | Пропускає елемент лише якщо він **відрізняється від попереднього** значення. | `.distinctUntilChanged()` |
| **`debounce(time)`** | Пропускає значення тільки якщо після нього минув вказаний час без нових викликів (для пошукового рядка). | `.debounce(400)` |
| **`take(n)`** | Обмежує потік першими `n` елементами та автоматично завершує його. | `.take(5)` |

---

### Приклад об'єднання операторів у ланцюжок:

Оператори `Flow` можна об'єднувати у зручні та читабельні ланцюжки обробки:

```kotlin
lifecycleScope.launch {
    getCounterFlow()
        .filter { it % 2 == 0 }                 // 1. Фільтруємо лише парні числа
        .map { "Парне число: $it" }             // 2. Перетворюємо число у рядок
        .onEach { Log.d(TAG, "Отримано: $it") }  // 3. Логуємо кожен крок
        .catch { e -> Log.e(TAG, "Помилка у Flow", e) } // 4. Безпечно перехоплюємо помилки
        .flowOn(Dispatchers.IO)                // 5. Виконуємо обчислення вище у фоновому потоці!
        .collect { result ->                   // 6. Отримуємо фінальний результат у Main Thread
            binding.tvResult.text = result
        }
}
```

> ⚠️ **Важливо:** Оператор **`flowOn(Dispatchers.IO)`** змінює диспатчер тільки для тих операцій, які написані *вище* нього у ланцюжку.

---

### Контекст виконання потоків у Flow (Context Preservation)

Щоб уникнути помилок при роботі з потоками, важливо пам'ятати два правила:

1. **За замовчуванням Flow виконується у потоці підписника:**
   Якщо ви викликаєте `.collect()` усередині `lifecycleScope.launch` (який за замовчуванням працює на `Dispatchers.Main`), то і код усередині `flow { ... }`, і сам збір даних `.collect()` виконуються **на Головному потоці (Main Thread)**.

2. **Куди приходить результат у `.collect { ... }`?**
   Результат у блоці `.collect { result -> ... }` **ЗАВЖДИ приходить у той потік, де була запущена корутина підписки** (у нашому випадку — у `Dispatchers.Main`). 

   Навіть якщо за допомогою `.flowOn(Dispatchers.IO)` ви перенесли важкі обчислення чи зчитування з диска у фоновий потік, блок `.collect { ... }` все одно виконається на Головному потоці, що робить оновлення UI усередині `collect` абсолютно безпечним!

## 3. Гарячі потоки: StateFlow та SharedFlow

На відміну від звичайного "холодного" `Flow`, **Гарячі потоки (Hot Streams)** працюють і зберігають дані у пам'яті **незалежно від того, чи є зараз активні підписники**.

### 1. `StateFlow` — Сучасна заміна `LiveData`
[`StateFlow`](https://developer.android.com/kotlin/flow/stateflow-and-sharedflow) — це спеціальний гарячий потік, який **завжди зберігає поточний стан** (останнє значення) і негайно віддає його кожному новому підписнику.

* Має обов'язкове початкове значення (`initialValue`).
* Зберігає лише **останнє** значення.
* Автоматично відфільтровує дублікати (якщо нове значення дорівнює попередньому, воно не надсилається знову).

#### Використання у ViewModel (Аналог LiveData):

```kotlin
class NewsViewModel : ViewModel() {

    // Приватний змінний потік
    private val _uiState = MutableStateFlow<String>("Завантаження...")
    
    // Публічний потік тільки для читання для UI
    val uiState: StateFlow<String> = _uiState.asStateFlow()

    fun loadNews() {
        viewModelScope.launch {
            val news = repository.fetchNews()
            _uiState.value = news // Просте оновлення значення
        }
    }
}
```

### 2. `SharedFlow` — Для одноразових подій (Events)
`SharedFlow` не має початкового значення. Він використовується для надсилання **подій**, які не є "станом екрану" (наприклад, показ `Toast`, `Snackbar` чи навігаційний перехід на інший екран).

---

## 4. Золотий стандарт ViewModel: Оператор `stateIn`

Найчастіше у репозиторії ви маєте звичайний холодний `Flow` (наприклад, з бази даних Room). Щоб перетворити його на `StateFlow` усередині `ViewModel`, використовується оператор **`stateIn`**:

```kotlin
class UserViewModel(repository: UserRepository) : ViewModel() {

    // Автоматично перетворює холодний Flow з бази у гарячий StateFlow
    val userState: StateFlow<User> = repository.getUserFlow()
        .stateIn(
            scope = viewModelScope,
            started = SharingStarted.WhileSubscribed(5000), // Золотий стандарт!
            initialValue = User.EMPTY
        )
}
```

> 💡 **Чому саме `SharingStarted.WhileSubscribed(5000)`?**
> Цей параметр каже: *"Тримай потік активним, поки є хоч один спостерігач. Якщо спостерігач зник (наприклад, екран перевернувся), почекай 5 секунд. Якщо за 5 секунд ніхто не підписався знову — зупини фоновий потік для економії ресурсів"*.

---

## 5. Безпечна підписка на StateFlow в Activity

Щоб підписатися на `StateFlow` убезпечено від витоків пам'яті при згортанні екрану, використовується розширення **`collectAsStateWithLifecycle`** або `repeatOnLifecycle`:

1. Додайте залежність у `build.gradle.kts`:
   ```kotlin
   implementation("androidx.lifecycle:lifecycle-runtime-ktx:2.8.0")
   ```

2. Підпишіться у `MainActivity`:
   ```kotlin
   class MainActivity : AppCompatActivity() {

       private val viewModel: NewsViewModel by viewModels()

       override fun onCreate(savedInstanceState: Bundle?) {
           super.onCreate(savedInstanceState)

           // Автоматично зупиняє збір даних, коли екран згортається у фон!
           lifecycleScope.launch {
               repeatOnLifecycle(Lifecycle.State.STARTED) {
                   viewModel.uiState.collect { news ->
                       binding.tvNews.text = news
                   }
               }
           }
       }
   }
   ```

## Порівняння: LiveData vs StateFlow

| Характеристика | `LiveData` | `StateFlow` |
| :--- | :--- | :--- |
| **Прив'язка до Android** | Так (`androidx.lifecycle`) | Ні (Чистий Kotlin) |
| **Початкове значення** | Необов'язкове | **Обов'язкове** |
| **Сумісність із Compose** | Потребує конвертації | **Першокласна нативна підтримка** |
| **Оператори трансформації** | Обмежені (`map`, `switchMap`) | Багатий вибір операторів Kotlin Flow |

---

## Підсумок

* **`Flow`** — це холодний реактивний потік асинхронних даних.
* **`StateFlow`** — це гарячий потік, що зберігає поточний стан UI (сучасний замінник `LiveData`).
* **`SharedFlow`** — гарячий потік для одноразових подій (Toast, Навігація).
* **`stateIn(SharingStarted.WhileSubscribed(5000))`** — перетворює `Flow` у `StateFlow` з паузою в 5 секунд при повороті екрану.
* **`repeatOnLifecycle(STARTED)`** — безпечний спосіб підписки на `StateFlow` у `Activity`.
