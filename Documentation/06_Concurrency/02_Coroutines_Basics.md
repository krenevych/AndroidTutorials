# Вступ до Kotlin Coroutines: Асинхронне програмування в синхронному стилі

Ласкаво просимо до світу **Корутин (Kotlin Coroutines)**! Корутини — це офіційний, сучасний та найпотужніший спосіб розробки асинхронного коду в Android.

### Що таке асинхронність у синхронному стилі?
У минулому уроці ми бачили, що при роботі з колбеками код перетворюється на "Callback Hell" (вкладену локшину коду).

**Корутини дозволяють писати фоновий асинхронний код так, ніби це звичайний послідовний (синхронний) код:**

```kotlin
// Корутини: виглядає як звичайний послідовний код, але НЕ блокує UI!
lifecycleScope.launch {
    val city = loadCity()                   // 1. Отримуємо місто (фоновий потік)
    binding.tvCityValue.text = city         // 2. Одразу оновлюємо назву міста на UI

    val temperature = loadTemperature(city) // 3. Завантажуємо температуру для міста (фоновий потік)
    binding.tvTemperatureValue.text = "$temperature°C" // 4. Оновлюємо температуру на UI
}
```
Зверніть увагу: жодних `Handler`, `Thread`, чи вкладених колбеків! Код читається зверху вниз, рядок за рядком.

## 2. Ключове поняття: `suspend` функції

**`suspend` (призупиняюча) функція** — це функція, яка здатна **тимчасово призупиняти (suspend)** своє виконання, не блокуючи потік (Thread), на якому вона була запущена, та **відновлювати (resume)** роботу з того ж місця після завершення фонової операції.

```kotlin
// Ключове слово suspend дозволяє функції виконувати асинхронні задачі без блокування потоку
suspend fun loadCity(): String {
    delay(2000) // Призупиняє корутину на 2 секунди, але НЕ блокує UI Thread!
    return "Київ"
}
```

### Магія `suspend`: Призупинення без блокування
* **Призупинення (Suspend):** Коли корутина викликає `suspend` функцію (наприклад, мережевий запит чи читання файлу), виконання цієї корутини ставиться "на паузу", а потік виконання (наприклад, Main Thread) миттєво звільняється для малювання анімацій та обробки кліків.
* **Відновлення (Resume):** Як тільки фонова задача завершується, корутина "розморожується" і продовжує роботу з наступного рядка коду.

> ⚠️ **Головне правило `suspend`:** 
> Призупиняючу функцію можна викликати **тільки з іншої `suspend` функції** або всередині **білдера корутини** (наприклад, `launch` або `async`).

## 3. Диспатчери (`Dispatchers`): Де виконувати корутину?

**`CoroutineDispatcher`** визначає, на якому саме потоці (або пулі потоків) буде виконуватися ваша корутина.

В Android використовуються 3 основні диспатчери:

| Диспатчер | Для яких задач використовувати | Приклад |
| :--- | :--- | :--- |
| **`Dispatchers.Main`** | Для роботи з UI та швидких операцій на Головному потоці. | Оновлення `TextView`, показ діалогів, обробка кліків. |
| **`Dispatchers.IO`** | Для важких операцій введення/виведення (I/O). | Запити в мережу (Retrofit), читання/запис баз даних (Room), файлів. |
| **`Dispatchers.Default`** | Для важких обчислень, що навантажують процесор (CPU). | Сортування великих масивів, парсинг великих JSON, обробка відео/зображень. |
| **`Dispatchers.Unconfined`** | Запускає корутину в поточному потоці без прив'язки. | Вузькоспеціалізовані тести. |

## 4. Контекст та запуск корутин (Coroutine Builders)

### Що таке `CoroutineScope` (Область видимості корутин)?

Корутини не можуть просто "існувати самі по собі" у повітрі. Будь-яка корутина обов'язково має запускатися усередині **`CoroutineScope`**.

`CoroutineScope` відповідає за **управління життєвим циклом корутин** та реалізує принцип **Structured Concurrency (Структурована багатопотоковість)**:
* Вона контролює всі корутини, запущені в межах цієї області видимості.
* Якщо скасовується сам `CoroutineScope`, то **автоматично скасовуються абсолютно всі корутини**, запущені всередині нього. Це повністю запобігає витокам пам'яті (Memory Leaks) та даремній витраті ресурсів.

#### Приклад створення та використання ручного CoroutineScope:

```kotlin
class MainActivity : AppCompatActivity() {

    // Створюємо власний ручний CoroutineScope, прив'язаний до Main Thread
    private val scope = CoroutineScope(Dispatchers.Main)

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        // ...

        binding.btnLoad.setOnClickListener {
            // Запускаємо корутину у нашому ручному Scope
            scope.launch {
                val city = loadCity()
                binding.tvCityValue.text = city

                val temperature = loadTemperature(city)
                binding.tvTemperatureValue.text = "$temperature°C"
            }
        }
    }

    override fun onDestroy() {
        super.onDestroy()
        // Обов'язково скасовуємо Scope при знищенні екрану, щоб не було Memory Leak!
        scope.cancel()
    }
}
```

Як бачите, при використанні ручного `CoroutineScope` розробник мусить пам'ятати про виклик `scope.cancel()` у методі `onDestroy()`.

### Готові життєво-залежні Scope в Android

Щоб розробникам не доводилося скасовувати корутини вручну, Android надає готові Scope, які **автоматично прив'язані до життєвого циклу UI-компонентів**:

* **`lifecycleScope`** — доступний усередині `Activity` або `Fragment`. Усі корутини в цьому Scope автоматично скасовуються у момент виклику `onDestroy()`.
* **`viewModelScope`** — доступний усередині `ViewModel`. Усі фонові корутини в цьому Scope автоматично скасовуються при закритті екрану у момент виклику `onCleared()`.

### Основні білдери корутин та перемикання контексту:

#### 1. `launch` (Запустив і забув — Fire and Forget)
Використовується, коли вам потрібно просто запустити асинхронне завдання і вам не потрібно повертати з нього результат. 

```kotlin
lifecycleScope.launch(Dispatchers.IO) {
    // Фонова задача без повернення результату
    saveDataToDatabase()
}
```

Білдер `launch` повертає об'єкт **`Job`**. За допомогою цього об'єкта ви можете:
* **`job.cancel()`** — скасувати виконання корутини у будь-який момент.
* **`job.join()`** — призупинити поточну корутину та зачекати, поки `job` повністю завершить свою роботу.

```kotlin
// Запускаємо корутину і зберігаємо посилання на Job
val job = lifecycleScope.launch(Dispatchers.IO) {
    saveDataToDatabase()
}

// При необхідності можемо зачекати її завершення у іншій корутині
job.join()
```

#### 2. `async` / `await` (Отримання результату / Паралельне виконання)
Використовується, коли вам потрібно запустити фонову задачу і **отримати з неї результат**. 

Білдер `async` повертає об'єкт **`Deferred<T>`** (який є безпосереднім нащадком інтерфейсу `Job`). Це означає, що `Deferred` успадковує абсолютно всі можливості `Job` (наприклад, можливість скасування через `cancel()`), але додатково надає метод **`.await()`** для отримання обчисленого значення типу `T`.

Це ідеально для **паралельного запуску кількох задач**:

```kotlin
lifecycleScope.launch(Dispatchers.Main) {
    // Запускаємо дві фонові задачі ПАРАЛЕЛЬНО
    val userDeferred = async(Dispatchers.IO) { fetchUser() }
    val postsDeferred = async(Dispatchers.IO) { fetchPosts() }

    // Чекаємо завершення ОБОХ задач через await()
    val user = userDeferred.await()
    val posts = postsDeferred.await()

    // Оновлюємо UI
    showUserProfile(user, posts)
}
```

#### Очікування масивів задач: `awaitAll()` та `joinAll()`

Коли ви запускаєте багато паралельних корутин (наприклад, обробку списку файлів чи запити для кількох елементів), чекати на кожну окремо через `.await()` чи `.join()` незручно. Для цього в Kotlin є згруповані функції:

* **`awaitAll(...)`** — чекає на завершення **усіх** переданих `Deferred<T>` корутин і повертає список їхніх результатів `List<T>`.
  ```kotlin
  lifecycleScope.launch(Dispatchers.Main) {
      // 1. Запускаємо 3 фонові задачі ПАРАЛЕЛЬНО
      val task1 = async(Dispatchers.IO) { fetchPriceForProduct(1) }
      val task2 = async(Dispatchers.IO) { fetchPriceForProduct(2) }
      val task3 = async(Dispatchers.IO) { fetchPriceForProduct(3) }

      // 2. Чекаємо завершення УСІХ задач і отримуємо список результатів List<Int>
      val prices: List<Int> = awaitAll(task1, task2, task3)
  }
  ```

* **`joinAll(...)`** — чекає на завершення **усіх** переданих `Job` корутин (від `launch`), не повертаючи значень.
  ```kotlin
  val job1 = launch { downloadPart1() }
  val job2 = launch { downloadPart2() }

  // Дочікуємося завершення обох завантажень
  joinAll(job1, job2)
  ```

> 💡 **Різниця між `join()` та `await()`:**
> * `job.join()` (для `launch`) — просто **чекає завершення** роботи корутини, не повертаючи жодного значення.
> * `deferred.await()` (для `async`) — **чекає та повертає** обчислене значення назад.

#### 3. `withContext` (Зміна диспатчера / потоку "на льоту")
Дуже зручна `suspend`-функція, яка дозволяє всередині корутини тимчасово переключити потік (наприклад, переключитися на `Dispatchers.IO` для завантаження файлу, а після завершення повернутися на `Dispatchers.Main`).

```kotlin
lifecycleScope.launch(Dispatchers.Main) { // 1. Починаємо на Main Thread
    
    binding.progressBar.isVisible = true

    // 2. Переключаємося на фоновий потік IO для завантаження
    val data = withContext(Dispatchers.IO) {
        fetchDataFromNetwork() // Тривала фонова задача
    }

    // 3. Автоматично повертаємося на Main Thread для UI!
    binding.tvResult.text = data
    binding.progressBar.isVisible = false
}
```

## Підсумок

* **Корутини** дозволяють писати асинхронний код у простий та читабельний **послідовний спосіб**.
* **`suspend` функції** можуть "призупиняти" виконання корутини, не блокуючи при цьому потік виконання (UI Thread).
* **`Dispatchers`** визначають, де виконується корутина: `Main` (для UI), `IO` (для мережі/диска), `Default` (для важких обчислень CPU).
* **`launch`** використовується для запуску задач без повернення значення, а **`async` / `await`** — для паралельного виконання та отримання результату.
* **`withContext`** дозволяє елегантно переключати диспатчери (потоки) всередині однієї корутини.
