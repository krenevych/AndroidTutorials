# Холодні реактивні потоки: Kotlin Flow

У сучасній Android-розробці для передачі та відстеження асинхронних даних використовуються реактивні потоки **Kotlin Flow**. Вони є сучасною, потужною та гнучкою заміною застарілому `LiveData`.

У цьому уроці ми розглянемо **Холодні потоки (Cold Flow)** та їхні базові оператори.

---

## 1. Що таке Kotlin Flow та його базові оператори (`flow`, `emit`, `collect`)

Якщо звичайна `suspend` функція повертає лише один результат, то **`Kotlin Flow`** — це асинхронний потік, який здатен видавати **послідовність багатьох значень протягом часу** (наприклад, відсотки завантаження файлу, живі координати GPS або оновлення лічильника).

```
[ Джерело Flow ] ─── (значення 1) ───► (значення 2) ───► (значення 3) ───► [ Споживач collect ]
```

Робота з базовим `Flow` будується на трьох основних елементах:

### 1. `flow { ... }` (Білдер створення потоку)
Блок-білдер `flow { ... }` створює новий потік даних. Код усередині цього блоку є асинхронним і може кликати будь-які `suspend` функції (наприклад, `delay(1000)` чи мережеві запити), не блокуючи Main Thread.

### 2. `emit(value)` (Надсилання значення у потік)
`emit()` — це `suspend` функція, яка викликається усередині білдера `flow { ... }` для **надсилання нового значення** споживачам.

### 3. `collect { value -> ... }` (Збирання даних з потоку)
`collect()` — це термінальна `suspend` функція, яка **запускає виконання потоку та приймає кожне надіслане значення**. Оскільки `collect()` є `suspend` функцією, викликати її можна **тільки усередині корутини** (наприклад, `lifecycleScope.launch`) або з іншої `suspend` функції.

---

### Приклад використання `flow`, `emit` та `collect`:

Уявіть, що нам потрібно реалізувати асинхронний лічильник, який щосекунди надсилає нове число від 1 до 5 та оновлює його на екрані:

> 📦 **Початковий проект:**
> Ви можете завантажити або склонувати заготовку цього проекту з GitHub за посиланням: [krenevych/Concurrency](https://github.com/krenevych/Concurrency) (гілка **`main`**, модуль **`flowfibonacci`**).
> 
> 💡 **Готовий розв'язок (для холодних потоків Flow):**
> Повний робочий код прикладів з холодними потоками можна переглянути на гілці **`flow_end`** (модуль **`flowfibonacci`**).

```kotlin
// 1. Створення Flow за допомогою білдера flow та функції emit()
fun getCounterFlow(): Flow<Int> = flow {
    for (i in 1..5) {
        delay(1000) // ⚡ Неблокуюча затримка корутини
        emit(i)     // ⚡ Передаємо нове значення у потік
    }
}

// 2. Підписка та збирання даних за допомогою suspend-функції collect()
lifecycleScope.launch {
    getCounterFlow().collect { value ->
        // Отримуємо кожне нове значення з потоку і оновлюємо UI
        binding.tvCounter.text = "Лічильник: $value"
    }
}
```

---

### `Flow` є "Холодним" (Cold Stream)

За замовчуванням звичайний `Flow` є **Холодним потоком даних**:
* Код усередині білдера `flow { ... }` **взагалі не виконується**, поки у якійсь корутині не викликано метод `.collect()`.
* Для кожного нового підписника (кожного нового виклику `.collect()`) блок `flow { ... }` запускається і виконується з нуля.
* Якщо корутину-споживача скасовано (наприклад, при закритті екрану), виконання коду всередині `flow { ... }` **автоматично зупиняється та скасовується**.

## 2. Основні оператори Flow

Подібно до звичайних колекцій у Kotlin, `Flow` надає багатий набір операторів для трансформації, фільтрації та обробки даних перед тим, як вони потраплять у підписник `.collect()`.

### Огляд популярних операторів Flow:

| Оператор | Призначення / Опис | Приклад |
| :--- | :--- | :--- |
| **`onStart { ... }`** | Виконується **перед** початком емісії елементів (зручно для ввімкнення ProgressBar). | `.onStart { Log.d(TAG, "Початок") }` |
| **`map { ... }`** | Перетворює кожний елемент потоку в інше значення. | `.map { price -> "$price $" }` |
| **`filter { ... }`** | Пропускає тільки ті елементи, які відповідають умові. | `.filter { num -> num % 2 == 0 }` |
| **`onEach { ... }`** | Виконує побічну дію (наприклад, логування) для кожного елемента, не змінюючи його. | `.onEach { Log.d(TAG, "Елемент: $it") }` |
| **`catch { e -> ... }`** | Безпечно перехоплює винятки, вибиті усередині Flow, запобігаючи крашу. | `.catch { e -> Log.e(TAG, "Помилка", e) }` |
| **`onCompletion { cause -> ... }`** | Виконується при завершенні Flow. Параметр `cause == null`, якщо потік успішно дійшов до кінця сам, або містить виняток, якщо потік було скасовано чи він упав. | `.onCompletion { cause -> if (cause == null) Log.d(TAG, "Успішно завершено") }` |
| **`flowOn(Dispatcher)`** | Змінює диспатчер виконання для усіх операторів, які знаходяться **вище** нього. | `.flowOn(Dispatchers.IO)` |
| **`distinctUntilChanged()`** | Пропускає елемент лише якщо він **відрізняється від попереднього** значення. | `.distinctUntilChanged()` |
| **`debounce(time)`** | Пропускає значення тільки якщо після нього минув вказаний час без нових викликів (для пошукового рядка). | `.debounce(400)` |
| **`take(n)`** | Обмежує потік першими `n` елементами та автоматично завершує його. | `.take(5)` |

> 💡 **Як перевіряти причину завершення в `onCompletion`?**
>
> Оператор `onCompletion { cause -> ... }` приймає параметр `cause: Throwable?`:
> * **`cause == null`** — потік видав усі дані та **успішно завершився сам**.
> * **`cause != null`** — потік був **скасований** (наприклад, корутину скасували при закритті екрану, і `cause` дорівнює `CancellationException`) або перерваний помилкою.

---

### Контекст виконання потоків у Flow (Context Preservation)

1. **За замовчуванням Flow виконується у потоці підписника:**
   Якщо ви викликаєте `.collect()` усередині `lifecycleScope.launch` (на `Dispatchers.Main`), то і код усередині `flow { ... }`, і збір даних `.collect()` виконуються **на Головному потоці (Main Thread)**.

2. **Куди приходить результат у `.collect { ... }`?**
   Результат у блоці `.collect { result -> ... }` **ЗАВЖДИ приходить у той потік, де була запущена корутина підписки** (Main Thread).
   Навіть якщо за допомогою `.flowOn(Dispatchers.IO)` ви перенесли важку фонову роботу у потік `IO`, блок `.collect { ... }` все одно виконається на Головному потоці, що робить оновлення UI усередині `collect` абсолютно безпечним!

---

### Приклад об'єднання операторів у ланцюжок:

```kotlin
lifecycleScope.launch {
    getCounterFlow()
        .onStart { Log.d(TAG, "Запуск емісії Flow!") } // 1. Спрацьовує перед початком
        .filter { it % 2 == 0 }                         // 2. Фільтруємо лише парні числа
        .map { "Парне число: $it" }                     // 3. Перетворюємо число у рядок
        .onEach { Log.d(TAG, "Отримано: $it") }          // 4. Логуємо кожен крок
        .catch { e -> Log.e(TAG, "Помилка у Flow", e) } // 5. Безпечно перехоплюємо помилки
        .onCompletion { cause ->                       // 6. Виконується при завершенні або скасуванні
            if (cause == null) {
                Log.d(TAG, "Потік успішно завершився сам!")
            } else {
                Log.d(TAG, "Потік зупинено через скасування або помилку: $cause")
            }
        }
        .flowOn(Dispatchers.IO)                        // 7. Виконуємо обчислення вище у фоновому потоці!
        .collect { result ->                           // 8. Отримуємо фінальний результат у Main Thread
            binding.tvResult.text = result
        }
}
```

## 3. Альтернативний спосіб підписки: Термінальний білдер `launchIn(scope)`

Зазвичай для підписки на `Flow` використовується конструкція `scope.launch { flow.collect { ... } }`. 

Проте в Kotlin є більш лаконічний термінальний оператор **`launchIn(scope)`**. У комбінації з оператором **`onEach`** він дозволяє підписатися на потік без потреби загортати весь ланцюжок у зовнішній блок `launch`:

```kotlin
getCounterFlow()
    .onEach { value ->
        // 1. Обробляємо кожний елемент
        binding.tvCounter.text = "Лічильник: $value"
    }
    .catch { e ->
        Log.e(TAG, "Помилка у Flow", e)
    }
    .launchIn(lifecycleScope) // 2. Автоматично створює корутину і запускає collect() у вказаному Scope!
```

**Як це працює під капотом?**
Виклик `flow.onEach { ... }.launchIn(scope)` є абсолютно еквівалентним запису:
`scope.launch { flow.onEach { ... }.collect() }`




---

## Підсумок

* **`Flow`** — це холодний асинхронний потік послідовності значень.
* **`flow { ... }`** створює потік, **`emit()`** надсилає значення, а **`collect()`** запускає потік та приймає значення.
* **Cold Stream:** Код усередині `flow { ... }` взагалі не виконується до виклику `.collect()`.
* **`flowOn(Dispatchers.IO)`** переносить виконання всіх операторів, написаних *вище* нього, у фоновий потік.
* **`collect { ... }`** завжди виконується на потоці підписника (Main Thread).
