# Що таке Application в Android?

Коли ми говоримо про "Application" (застосунок) в контексті Android, ми можемо мати на увазі дві різні речі: 
1. Програму в цілому (як набір екранів, ресурсів та коду, який встановлює користувач).
2. Конкретний клас `android.app.Application`, який є базовим класом для підтримки глобального стану вашого застосунку.

У цьому туторіалі ми зосередимося на другому понятті — класі `Application`, для чого він потрібен, як працює його життєвий цикл і як створити власний.

## 1. Застосунок як єдиний процес

Android базується на ядрі Linux. Це означає, що система використовує класичні механізми безпеки та ізоляції Linux для роботи мобільних застосунків.

Коли ви встановлюєте застосунок, система Android призначає йому **унікальний ідентифікатор користувача (User ID, або UID)**. 
За замовчуванням кожен застосунок запускається у своєму **власному процесі Linux** і працює під своїм унікальним UID. 

Це створює так звану **Пісочницю (Application Sandbox)**:
* **Ізоляція пам'яті:** Ваш застосунок має свій власний обсяг виділеної оперативної пам'яті (RAM). Інші застосунки не можуть прямо зазирнути у вашу пам'ять, прочитати змінні з вашої `MainActivity` або отримати доступ до вашого об'єкту `Application`. 
* **Ізоляція файлів:** Усі файли, бази даних (наприклад, SQLite/Room) та налаштування (SharedPreferences), які зберігає ваш застосунок у своїй внутрішній папці, доступні лише йому (оскільки інші програми мають інші UID і не мають прав доступу до цих файлів на рівні Linux).
* **Життєвий цикл процесу:** Процес створюється, коли потрібно запустити будь-який компонент застосунку (наприклад, користувач клікає на іконку). Але **система Android самостійно вирішує, коли "вбити" цей процес**. На відміну від комп'ютера, де ви закриваєте вікно "хрестиком", на Android застосунки працюють у фоні, доки системі не знадобиться оперативна пам'ять для інших (наприклад, активних) програм. Тоді система без попередження вбиває найстаріші або найменш важливі процеси (разом з вашим класом `Application`).

Коли процес стартує:
1. Система ініціалізує нове віртуальне середовище.
2. **Створює єдиний екземпляр класу `Application`** (або вашого власного класу-спадкоємця).
3. Тільки після цього створює першу (головну) `Activity`.

Клас `Application` — це об'єкт, який гарантовано живе найдовше в вашій програмі. Він створюється найпершим і знищується останнім (разом із самим процесом Linux).

## 2. Створення власного класу Application?

За замовчуванням Android використовує стандартний системний клас `Application`. Але ви можете створити свій власний клас, який буде наслідувати стандартний. 

Це буває необхідно для:
* **Глобальної ініціалізації:** Це ідеальне місце для налаштування бібліотек, які потрібні програмі одразу при старті (наприклад: аналітика Firebase, системи логування (як Timber), бази даних (Room) або Dependency Injection (Hilt / Dagger)).
* **Зберігання глобального стану:** Іноді тут зберігають змінні, до яких потрібно мати доступ з будь-якого екрану програми. *(Примітка: хоча це можливо, сьогодні це вважається поганою практикою (anti-pattern) — для зберігання стану краще використовувати `ViewModel`, бази даних або SharedPreferences).*

## 3. Як створити свій Application-клас

Щоб додати власний клас Application, потрібно зробити два кроки: написати код класу та зареєструвати його в Маніфесті.

### Крок 1: Створення класу
Створіть новий Kotlin-файл (наприклад, `MyApplication.kt`) поруч із вашою `MainActivity`:

```kotlin
package com.example.myapp

import android.app.Application
import android.util.Log

// 1. Обов'язково наслідуємося від базового класу Application()
class MyApplication : Application() {

    // 2. Перевизначаємо метод onCreate(), який викликається при старті процесу
    override fun onCreate() {
        super.onCreate()
        
        Log.d("MyApplication", "Застосунок стартував! Тут можна ініціалізувати бібліотеки.")
        
        // Наприклад: FirebaseApp.initializeApp(this)
    }
}
```

### Крок 2: Реєстрація в AndroidManifest.xml
Якщо ви просто створите клас, Android про нього не дізнається. Ви повинні чітко вказати системі використовувати саме ваш клас замість стандартного.

Відкрийте `AndroidManifest.xml` і додайте атрибут `android:name` всередину тегу `<application>`:

```xml
<manifest xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:tools="http://schemas.android.com/tools">

    <!-- Зверніть увагу на атрибут android:name=".MyApplication" -->
    <!-- Крапка перед назвою означає, що клас знаходиться у поточному пакеті (namespace) -->
    <application
        android:name=".MyApplication"  
        android:icon="@mipmap/ic_launcher"
        android:label="@string/app_name"
        android:theme="@style/Theme.MyApp">

        <activity android:name=".MainActivity" ... >
            <!-- ... -->
        </activity>

    </application>
</manifest>
```
Якщо ви забудете додати `android:name=".MyApplication"`, код вашого класу (зокрема метод `onCreate()`) **ніколи не виконається**.

## 4. Життєвий цикл Application

**Що взагалі таке життєвий цикл (Lifecycle)?**
В Android під "життєвим циклом" компонента розуміють набір спеціальних методів (колбеків, від англ. *callbacks*), які операційна система автоматично викликає в ключові моменти "життя" цього компонента. 
Головне правило: **розробник ніколи не викликає ці методи напряму** у своєму коді (ви не пишете `app.onCreate()`). Ви лише перевизначаєте їх (використовуючи ключове слово `override`), щоб дати інструкцію системі, що саме треба зробити, коли ця подія настане.

Клас `Application` має дуже простий життєвий цикл. Давайте розглянемо його основні колбеки:

* **`onCreate()`** 
  Викликається перед створенням будь-якої Activity, Service або Receiver у вашій програмі. Це місце для швидкої одноразової ініціалізації.
  > ⚠️ **Увага:** Не виконуйте тут важкі або довгі мережеві запити! Метод `onCreate` працює в головному потоці (Main Thread). Якщо ви "підвісите" цей метод, застосунок буде довго запускатися, і користувач може побачити чорний/білий екран або помилку ANR (Application Not Responding).

* **`onTerminate()`** 
  Цей метод викликається, коли система завершує роботу застосунку. **Але є величезний нюанс:** він спрацьовує *тільки* на емуляторах. На реальних пристроях Android система просто вбиває процес програми у пам'яті (без попередження) для звільнення ресурсів, тому метод `onTerminate()` **ніколи не викликається**. Не покладайтеся на нього для збереження даних! Для збереження даних використовуйте методи життєвого циклу `Activity` (наприклад, `onStop`).

* **`onLowMemory()` / `onTrimMemory(level: Int)`**
  Викликаються системою, коли на пристрої закінчується оперативна пам'ять. Якщо ваша програма тримає в пам'яті великі кеші (наприклад, колекцію завантажених зображень), це сигнал до того, що їх потрібно очистити, щоб систему не примусила "вбити" ваш застосунок повністю.

## 5. Життєвий цикл процесу та ADB

Життєвий цикл об'єкта `Application` фактично на 100% співпадає з життєвим циклом самого процесу Linux, у якому запущено ваш застосунок. Об'єкт `Application` створюється при виділенні пам'яті під процес, і знищується виключно тоді, коли система примусово завершує (вбиває) цей процес.

**Як переглянути процеси через ADB?**
Ви можете самостійно переконатися, що ваш застосунок працює як окремий процес Linux. Підключіть пристрій до комп'ютера та виконайте в терміналi (вкладка Terminal в Android Studio) команду:

```bash
adb shell ps -A
```
*(Ця команда покаже список усіх запущених процесів на пристрої).*

Щоб знайти процес саме вашого застосунку, відфільтруйте результат за назвою вашого пакету (namespace):

```bash
adb shell ps -A | grep com.example.myapp
```

У відповіді ви побачите таблицю, де ключовими є: 
* **USER** (UID, наприклад `u0_a123`) — унікальний ідентифікатор вашої "пісочниці".
* **PID** — ідентифікатор процесу.
* **NAME** — назва вашого пакету.

> 💡 **Корисна порада:** Стандартний вивід команди `ps` містить дуже багато колонок і може не поміщатися на екрані. Ви можете попросити ADB вивести лише конкретні колонки (наприклад, тільки PID та NAME):
> ```bash
> adb shell ps -A -o PID,NAME
> ```
> А щоб відфільтрувати список, але при цьому **зберегти заголовок таблиці** (щоб бачити назви колонок), використайте складніший фільтр (де `example` — частина назви вашого пакета):
> ```bash
> adb shell "ps -A -o PID,NAME" | grep -E "PID|example"
> ```

Якщо ви згорнете застосунок, відкриєте десяток інших важких ігор і Android "вб'є" ваш процес через брак пам'яті, ваш застосунок просто зникне з цього списку `ps`.

## Підсумок
* **`Application`** — це базовий клас Android, який представляє програму в цілому і живе найдовше (від старту процесу до його "вбивства").
* Власний клас `Application` створюється для глобальної ініціалізації (аналітики, баз даних) при старті програми.
* Щоб ваш клас запрацював, його обов'язково треба вказати в `AndroidManifest.xml` у тезі `<application android:name=".ВашКлас">`.
* Не виконуйте важкі операції в `onCreate()`, оскільки це сповільнить запуск програми.
* Ніколи не покладайтеся на `onTerminate()` для збереження даних.
